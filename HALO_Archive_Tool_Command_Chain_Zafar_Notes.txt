HALO ARCHIVE TOOL COMMAND CHAIN
Written notes for running the drone archival workflow

This is the command chain I use to test the HALO archival tool from start to finish. The main idea is that every mission gets one official mission ID. That same mission ID is used on the ground computer, on the drone, and for the ReSpeaker/audio session. This keeps the audio, PX4 ULog, metadata, code state, and status logs tied to the same test.

The workflow is:

1. Confirm I can reach the drone.
2. Create a mission archive on the ground computer.
3. Initialize the matching mission folder on the drone.
4. Start the drone-side mission agent automatically.
5. Record ReSpeaker audio into the drone mission folder.
6. Arm/disarm manually only when it is safe.
7. Let PX4 generate the ULog.
8. Automatically collect everything back into the ground archive.
9. Verify that the archive contains audio, PX4 logs, metadata, and status files.

============================================================
8. MAIN SCRIPTS IN THE TOOL
============================================================

There are four main scripts:

scripts/create_mission_archive.py
    Creates the ground archive, generates the mission ID, creates the matching drone folder, copies README/config/profile files, and saves code-state metadata.

scripts/collect_drone_data.py
    Pulls the drone-side mission folder back to the ground archive. It collects audio, metadata, status logs, ULog candidates, and PX4 logs when enabled.

scripts/halo_drone_mission_agent.py
    Runs on the drone. It creates the drone-side folders, starts ReSpeaker recording, writes status/final metadata, and prepares audio/bag/status outputs.

scripts/run_halo_mission.py
    Runs on the ground computer. This is the main orchestrator. It creates the mission archive, uploads/starts the drone agent, waits for completion, and runs collection automatically.

============================================================
17. WHEN EXACTLY TO ARM
============================================================

The script will print status lines. I wait for this:

Status: phase=running, audio=True, rosbag=False, flight=unavailable

That means:

- the archive exists
- the drone-side mission folder exists
- the drone agent is running
- the ReSpeaker audio recorder is active

At that point, I arm manually with the remote.

My sequence is:

1. Start run_halo_mission.py.
2. Wait for: Status: phase=running, audio=True.
3. Arm manually with the remote.
4. Let the motors run briefly.
5. Disarm manually.
6. Do not stop the terminal.
7. Let the script finish and collect automatically.

Since ROS2 flight state is currently unavailable, the script may not detect disarm yet. That is fine for now. I let it run until the duration ends, then it automatically collects the data.

22. CURRENT ROS2 TIMESYNC NOTE
============================================================

The archive workflow is working, but ROS2 flight-state/timesync topics were not visible during this test. The services were running, but ROS2 only showed:

/parameter_events
/rosout

PX4 and MicroDDS logs showed that topics were being created internally, including timesync_status, but ROS2 CLI was not discovering the /fmu/out topics.

For now, this does not block the archive workflow. It means:

- audio recording works
- mission folders work
- automatic collection works
- PX4 ULog collection works after arming
- ROS2-based disarm/failsafe detection still needs more debugging

Until ROS2 flight state is visible, I use duration-based finalization and manual arm/disarm.

24. WHAT HAS BEEN PROVEN SO FAR
============================================================

So far I have proven:

1. The ground computer can create a unique mission archive.
2. The drone can receive a matching mission folder with the same mission ID.
3. SSH key login works and avoids repeated password prompts.
4. The workflow works on the lab IP and also on a temporary home hotspot IP.
5. The drone-side agent can be uploaded and started by the ground orchestrator.
6. ReSpeaker audio can be recorded automatically into the drone mission folder.
7. The collection script can pull the audio back into the ground archive.
8. After manual arming/disarming, PX4 creates a ULog.
9. The archive tool can collect both ReSpeaker WAV and PX4 ULog into the same mission archive.
10. The mission ID ties the ground folder, drone folder, ReSpeaker session, metadata, and logs together.
