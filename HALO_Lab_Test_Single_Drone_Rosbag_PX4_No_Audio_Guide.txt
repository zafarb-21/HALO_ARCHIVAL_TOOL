HALO ARCHIVE TOOL LAB TEST GUIDE
Single-drone ROS bag + PX4 ULog test, no audio

These are my step-by-step notes for testing the latest archive tool update in the lab. For this specific test I am not using ReSpeaker audio. I only want ROS bags, PX4 ULogs, metadata, status logs, and the archive structure. Audio is still supported by the tool, but I am intentionally not enabling it for this run.

The main idea is:

1. Start the archive tool before my partner arms/offboards the drone.
2. The tool creates the mission archive on the ground computer.
3. The tool creates the matching mission folder on the drone.
4. The drone-side agent attempts ROS bag recording.
5. My partner arms/offboards/disarms the drone manually.
6. PX4 creates a ULog during the armed/offboard test.
7. The archive tool collects the ROS bag if available, the PX4 ULog, metadata, and status logs automatically afterward.

8. RUN THE SINGLE-DRONE ROS BAG + PX4 ONLY TEST

============================================================
10. WHEN TO TELL MY PARTNER TO ARM/OFFBOARD
============================================================

When I see that the mission agent is running and ROS bag capture has been started or attempted, I tell my partner:

Archive is running. You can arm/offboard now.

Then I let my partner run the offboard test.

The sequence should be:

1. I start run_halo_mission.py.
2. I wait for the agent-running/readiness line.
3. I tell my partner to arm/offboard.
4. Partner runs the test.
5. Partner lands/disarms.
6. I wait about 10 to 15 seconds after disarm.
7. I let the archive tool finalize and collect.

Safety note:
The script does not arm the drone. Arming is still done manually/offboard by the proper operator. For bench tests, props should be removed unless this is an approved prop/flight test.

============================================================
11. WHAT IF THE DRONE LANDS BEFORE 300 SECONDS?
============================================================

The --duration value is a maximum window.

If flight-state detection is working:
- the tool may detect landing/disarm
- it should wait the post-disarm delay
- then stop rosbag/audio if running
- then collect data early

If flight-state detection is not working:
- the tool will not know the drone landed
- it will keep running until 300 seconds
- then it will finalize and collect

If Ctrl+C safe handling was implemented:
- after the drone has landed/disarmed
- wait 10 to 15 seconds
- press Ctrl+C once
- the tool should attempt clean finalization and collection

If I am not sure Ctrl+C safe handling is working, I should just let the 300 seconds finish.

14. VERIFY ROS BAG COLLECTION
============================================================

Check both possible bag folder styles:

find "$MISSION_DIR" -path "*/ros_bags/*" -print | head -50

If ROS2 topics were visible, I expect rosbag files or a rosbag folder.

If no /fmu/out topics were visible, it is acceptable for the archive to contain a warning saying ROS bag recording could not start or no requested topics were available. The important thing is that the tool should not crash, and PX4 ULog collection should still happen.

============================================================
15. VERIFY THAT AUDIO WAS NOT REQUIRED
============================================================

For this test, I intentionally disabled audio. So I should not see a warning saying ReSpeaker audio was missing.

Check the collection manifest:

Look for fields/warnings related to:

audio disabled intentionally

If the archive has a warning about missing audio, that is a bug for this no-audio test mode.
