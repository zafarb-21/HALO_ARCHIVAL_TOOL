WHY THIS VERSION IS DIFFERENT
================================================================================

The previous issue was not PX4 and not ULogs.

PX4 ULogs were working because PX4 was logging internally.

The ROS bag issue was caused by ROS2 discovery on the ground PC. The drone could see /fmu topics, and multicast packets could reach the ground PC, but the ground PC did not reliably discover the PX4 ROS2 topics until the drone IP was added as a static peer.

The missing key is:

export ROS_STATIC_PEERS=10.249.98.97
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp

This file includes that setup before every ROS2 topic check, rosbag test, and archive-tool run.

================================================================================
SECTION 6 — CHECK /fmu TOPICS ON THE DRONE FIRST
================================================================================

IMPORTANT:
Run this drone-side topic check BEFORE checking ROS2 topics on the ground PC.

We observed that checking the ground PC first can produce:

NO FMU TOPICS SEEN

The repeatable order that worked is:

1. Confirm /fmu topics on the drone.
2. Restart the ground-PC ROS2 daemon.
3. Check /fmu topics on the ground PC with ROS_DOMAIN_ID=3 and the static peer.
4. Only then run the archival tool.

Run this from the GROUND PC:

ssh halo-d0012-home "bash -lc '
source /opt/ros/foxy/setup.bash
export ROS_DOMAIN_ID=3
export ROS_LOCALHOST_ONLY=0

ros2 daemon stop >/dev/null 2>&1 || true
sleep 1
ros2 daemon start >/dev/null 2>&1 || true
sleep 3

echo \"===== DRONE FMU TOPICS =====\"
ros2 topic list -t | sort | grep fmu || echo \"NO FMU TOPICS ON DRONE\"
'"

Expected good output includes:

/fmu/out/battery_status
/fmu/out/sensor_combined
/fmu/out/timesync_status
/fmu/out/vehicle_attitude
/fmu/out/vehicle_local_position
/fmu/out/vehicle_odometry
/fmu/out/vehicle_status

If the drone does NOT show /fmu topics, stop here and do not continue to the ground-PC check.

Once the single-drone run works, the swarm version should use the same ROS2 discovery principle:

- each drone needs the correct ROS_DOMAIN_ID
- each drone IP should be included in ROS_STATIC_PEERS
- ground-side rosbag can record all visible ROS2 topics
- PX4 ULogs/audio/metadata can still be collected per drone

For swarm with D0012-D0016, the static peers may look like:

export ROS_STATIC_PEERS=192.168.0.20,192.168.0.21,192.168.0.22,192.168.0.23,192.168.0.24

or whatever syntax the installed ROS2 Jazzy accepts for multiple peers.
